# Plan: VeoLink CE Modernization (Rebrand + Dependency/Security Refresh)

- **Status:** Phase 01 completed, Phases 02–05 pending
- **Created:** 2026-07-25
- **Scope:** Rebrand rapidvms → VeoLink - VMS Software Community Edition; assess and replace/update outdated, insecure source and 3rd-party components.

## Current-state assessment (verified 2026-07-25)

| Component | Version in tree | Released | Risk |
|---|---|---|---|
| OpenSSL | 1.0.2k | 2017, EOL 2019 | CRITICAL — unpatched CVEs, no TLS 1.3 |
| curl | 7.43.0 | 2015 | HIGH — many CVEs |
| civetweb | 1.8 | 2016 | HIGH — serves web UI + auth |
| protobuf | 3.2.0 | 2017 | MEDIUM |
| FFmpeg | 3.x (libavcodec 57) | 2016 | HIGH — decodes untrusted camera streams |
| live555 | 2016.10.11 | 2016 | HIGH — RTSP parsing of untrusted input |
| Poco | 1.5.4 | 2014 | MEDIUM |
| Qt | 5.7.1 (EOL) | 2016 | MEDIUM — toolchain: VS2013, Ubuntu 14.04 mkspecs |
| leveldb / sqlite / spdlog | 2015–2017 vintage | — | LOW–MEDIUM |

Application-level weaknesses:

- Default admin password `admin`, written into `.htpasswd` at startup ([vecvr/main/main.cpp](../../vecvr/main/main.cpp)).
- Password "encryption" via Qt `SimpleCrypt` (obfuscation, not crypto).
- Web UI over HTTP digest auth; TLS optional with self-signed certs.
- Build system assumes CentOS 7 / Ubuntu 14.04 / VS2013 — all EOL.
- Generated qmake Makefiles committed in `prj_linux/` (stale, still reference old names; regenerated by qmake).

## Acceptance criteria

- No `rapidvms`/`RapidStor`/`RapidClient` in user-visible strings, build outputs, or service units (upstream credit + LICENSE preserved — AGPL requirement).
- Full Linux build passes on a supported distro (Ubuntu 22.04/24.04).
- No EOL crypto/network library in the shipped artifact.
- No hardcoded/default credentials without forced first-run change.

## Notes / decisions

- LICENSE and veyesys copyright headers are intentionally preserved (AGPL obligation).
- HTTP digest realm changed to `veolink.local`; existing non-admin `.htpasswd` entries must be recreated after upgrade (admin entry is rewritten at startup).
- Translation files (`client/src/main/translations/*.ts`) still contain old brand strings; regenerate via `lupdate`/`lrelease` in Phase 05.
- 2026-07-25: Vendored 2017 ZLMediaKit/ZLToolKit (`vecvr/src/`) replaced by git submodule [AQ-VISION/html5stream](https://github.com/AQ-VISION/html5stream) at `vecvr/src/html5stream`. `vecvr/main/mediaserver.cpp` rewritten against the `mk_api` C SDK (shared `libmk_api.so`, headers `include/mk_api/`); Chromium `H264Parser` dependency dropped (H264Track self-parses SPS/PPS). SDK built with `ENABLE_SERVER/TESTS/WEBRTC/SRT/OPENSSL/FFMPEG/PACKAGING=OFF`; OpenSSL intentionally off until Phase 03 replaces the vendored 1.0.2k. Verified: SDK builds on Ubuntu 24.04 (gcc 13), smoke test linking `mk_env_init`/`mk_media_create`/`mk_media_input_h264` runs clean. Full `VeoLinkServer` link not verified locally (no qmake/Qt toolchain — Phase 02).
- 2026-07-25 (Phase 02, in progress): Qt track decision = **distro Qt 5.15** (`qtbase5-dev`/`qt5-qmake`); `.pro` files only need qtbase modules (`core sql network xml dbus widgets gui printsupport concurrent`), so `qt_build` was removed from the native `3rdparty/Makefile` target (kept for cross-compile). `rules.mk`/`rules-macos.mk`/`rules-pi3.mk` now auto-detect `VE_PATH` from `$PWD`. Committed generated `vecvr/prj_linux/Makefile` removed; root `.gitignore` added. Readme package list rewritten for Ubuntu 22.04/24.04 (CentOS 7 dropped). Minimal gcc-13/glibc-2.39 patches to vendored deps: `3rdparty/live555/liveMedia/include/Locale.hh` (guard `<xlocale.h>` — removed in glibc 2.26) and `3rdparty/protobuf/.../java/java_file.cc` (`FieldDescriptorCompare::operator()` marked `const`). 3rdparty baseline on Ubuntu 24.04: poco/openssl/leveldb/curl/protobuf/live555 build OK; **ffmpeg blocked on missing host `yasm`/`nasm`**; app subdirs blocked on missing Qt/qmake packages (host has no sudo — user must install `yasm nasm libtool qtbase5-dev qt5-qmake libqt5sql5-sqlite`).
